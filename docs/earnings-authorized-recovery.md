# Explicit recovery editions

An ordinary stopped run retains its original verdict, budget and artifacts.
Recovery requires a new private edition with an explicit source-bound user
authorization; a passing code test does not provide that authorization.

`earnings_acceptance_exception` supports a narrow case: a completed authenticated
final report review passed, but its measured usage exceeded the original budget.
The exception binds the exact review, staged candidate, original ceiling and
already incurred overrun. It replays source validation and the full review
contract before accepting the new edition. It runs no author or report reviewer,
does not reset the original budget, and cannot excuse unresolved content findings,
uncertain execution or other limits. Original usage remains visible.

For outstanding report defects, `targeted-remediation-v3` supports the exact-target
atomic correction plans from `earnings_corrections`, as well as the earlier field
path format. It rejects mixed plan formats and unchanged candidates. Each edition
has its own explicit review allowance and preserves the source's exhausted history.
An independent reviewer must accept the complete corrected report.

Both routes still require independently authored and reviewed signals before
publication. Neither imports a report into production or enables scheduling.
