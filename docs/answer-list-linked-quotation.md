# Linked answer-list and quotation proposal

This explicit offline contract permits exactly one unknown address shared by an
answer-passage list with retained valid support and one bare quotation field.
It differs from the old sole-answer-address quotation handler. Old versions and
default pipeline replay are unchanged.

Eligibility authenticates the complete original single retrieval, official clean
frozen verifier, prompts, route, protocol and exact failure. Every other original
ledger row, valid address and quotation remains subject to ordinary full source
inspection. Disposable inspection/schema diagnostics remove only the two invalid
typed positions, never a whole exchange ledger or unrelated row. They return no
replacement and carry no acceptance.

Fresh source adjudication must inspect the complete original question AND answer,
select one original indexed answer paragraph supporting the unchanged answer and
quotation, and preserve all valid positions/order and original prose. The two
invalid positions follow that same selected paragraph. Identifier similarity and
prior prose are not mapping authority. Additional fields, another unknown target,
question paragraphs, another answer turn, multiple replacement paragraphs,
quotation text edits and omitted valid references fail closed.

The canonical reservation path helper shares the original retrieval-address slot
and rejects alternate/legacy slots. This module does not initialize a reservation,
launch a model or create a successor/preparation. Those require separate exact
request/source/lock/accounting checks, a credible complete repair/author/signals/
NEW independent FULLreview funding path, and unchanged original models, cap,
correction rounds, resumes and full per-turn output reservation. A future complete
handler must authenticate fresh inspection and both real sessions, spend original
correction1 and preserve all original outputs/accounting. No activation or broad
adoption before an accepted canary plus exact remote report proof.
