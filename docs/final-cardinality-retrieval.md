# Final retrieval correction after cardinality failure

The opt-in `earnings_final_cardinality_retrieval` path accepts exactly a closed,
authenticated first retrieval repair whose frozen validator reports
`Retrieval requires four to eighteen passage selections`. It preserves both
real sessions and their full usage, original model routes and lifecycle cap.
The existing inspection-failure handler is unchanged.

A distinct canonical final-retrieval reservation spends original correction 2.
It requires fresh complete source inspection and full original validation;
it does not truncate selections, infer references or mutate either prior output.
Only a completed authenticated repair can prepare a continuation. Author and
signals still run, followed by a new independent full review at round 2. No
further correction is available. Source/currentness, request, canonical-slot,
legacy-usage and lock checks remain mandatory before activation. Worker per-turn
input bounds and full output reservation remain unchanged. Publication alone
neither activates a case nor proves report acceptance.

The separate `earnings_final_cardinality_resume` preparation is opt-in for
proven closed local budget/checkpoint stops only. It uses the normal bounded
same-role checkpoint selector and restore verifier. Every failed session and
charge remains included alongside the successful fresh resume. The exact
original context, bindings, model, remaining allowance and full source/schema
validation remain mandatory. Unknown executions and missing checkpoints reject.
The original completed-job validator and preparation remain unchanged.

Resume admission uses the read-only `canonical_plan` guard. It authenticates
both existing canonical reservations through the original frozen lineage,
meters all closed failed attempts, requires the next unused bounded sibling,
and rejects any alternate or normalized legacy reservation for the lifecycle.
It returns exact reservation hashes and cumulative/remaining usage without
creating a slot or request. The fresh-slot guard is not repurposed for resumes.
