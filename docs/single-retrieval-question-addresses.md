# Explicit single-retrieval question-address recovery

`earnings_single_retrieval_questions` has separate reservation and preparation
versions. Existing answer-only, quoted-answer and default replay rules remain
unchanged. It accepts one unknown address in one original question-paragraph
field of an otherwise complete original exchange ledger. Only that invalid
position can change; valid IDs and their order, every other row, question/answer
prose, quotations and other output remain immutable.

The clean original frozen verifier authenticates the sole completed retrieval,
its exact prompt/model/protocol, original usage and failure. Inspection outside
the invalid typed ID retains the entire exchange ledger. For schema checking
only, a diagnostic placeholder contains complete original question membership;
it is never a chosen replacement, evidence mapping, prepared output or accepted
repair. Fresh model adjudication must inspect every bound question and answer
scope and select only supported original question paragraphs. Similar IDs and
prior prose are never mapping authority. Local validation and completion enforce
the same typed-position restriction and fresh source inspection.

Only `reporting/repairs/retrieval-addresses/<original-run>` can be reserved.
Other canonical or legacy reservations mentioning that original report block a
new attempt. Historical executions replay their own clean pinned producer.
Success carries both distinct charged sessions and spends original correction
round one. Author, signals and fresh independent full review remain required
within original model routes, total tokens, correction/resume and full output
reservations. No code publication or offline preflight authorizes model spend,
retry of uncertain execution, independent-review waiver or report completion.
