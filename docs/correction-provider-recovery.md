# Failed correction proposer

`earnings_correction_provider_recovery.initialize(seed, output, authorization)`
creates one separately authorized edition after an observed empty proposer response
with a terminal `server_error`. It does not retry an uncertain process or reuse the
initial-analysis overload recovery contract.

The original frozen correction implementation must reproduce the entire prompt.
The failed session, runtime identity, request, observed exit, original snapshot and
all original source/code bindings are verified. Partial/completed output, unknown
or nonzero recorded usage, other errors, additional requests and changed sources
are rejected. Recorded zero usage remains explicitly uncertain for provider billing.

Authorization binds the original protocol hash and chooses `preserve` or explicitly
`uncapped` token accounting. Used rounds, remaining original rounds and inherited
usage cannot change. The failed attempt remains immutable. The successor's first
proposer receives the exact original prompt and model settings. Independent report
review and independent signal review remain mandatory.

This API does not launch work itself. Persist its new reservation privately, verify
remote bytes, and use the usual bounded coordinator and execution locks. A second
failure cannot be initialized through this API. Production completion still requires
fresh source equivalence, import and later remote verification.
